# Задание: «Цифровой деканат будущего»

Номинация «Вайб-кодинг», MGIMO AI Challenge (2-й межвузовский промпт-хакатон).
Источник: https://challenge.mgimo.ai/cabinet/nominations/vibe-coding

**Дедлайн: 22 ноября 2026, 23:59 МСК.** Прототип должен работать до 28 ноября (объявление итогов).

## Суть
Рабочий прототип личного кабинета студента, собранный с помощью ИИ-ассистентов:
всё в одном месте, удобно, красиво, полноценно с телефона, безопасно.

## Обязательное ядро
- [ ] **Вход и профиль** — логин/пароль; ФИО, факультет, направление, курс, группа
- [ ] **Расписание** — сегодня и неделя, аудитория, преподаватель, заметные изменения/переносы
- [ ] **Успеваемость** — оценки и зачёты по дисциплинам, сессия, общая картина «как дела»
- [ ] **Заявки и справки** — заказ справки / подача заявления онлайн + статус заявки
- [ ] **Уведомления** — новости деканата, напоминания о дедлайнах и изменениях

Свои идеи приветствуются; важнее продуманность связки разделов, чем их число.

## Требования
- [ ] Работающий прототип по ссылке (не макет/Figma): войти → расписание/оценки → подать заявку → увидеть статус
- [ ] Стек любой, но адекватный и масштабируемый
- [ ] Код пишут ИИ-ассистенты
- [ ] Мобильная версия: все сценарии работают от 360 px
- [ ] Только вымышленные данные; не подключаться к реальным системам вуза (парсинг открытых данных, например расписания, разрешён)
- [ ] На сайте явно указано: концепт для конкурса, не официальный сервис
- [ ] Без официального логотипа вуза (свой — можно)
- [ ] Сторонние библиотеки/шрифты/иконки/картинки — только с разрешающей лицензией
- [ ] Безопасность:
  - [ ] студент видит только свои данные (чужой профиль/заявка не открываются подменой URL/ID)
  - [ ] пароли хранятся в виде хешей
  - [ ] ключи и секреты (в т.ч. от ИИ) не в коде и не в браузере
- [ ] Доступ из России без VPN, работает до 28 ноября
- [ ] Минимум 2 тестовых аккаунта студентов с разными данными (+ аккаунт сотрудника, если есть)

## Что отправить (капитан, блок «Моя работа»)
1. Ссылка на прототип + тестовые логины/пароли — в комментарии
2. Исходный код — репозиторий с доступом для жюри (или архив)
3. Описание процесса (PDF/документ со скриншотами):
   - какую проблему решает, почему такие разделы (опрос однокурсников — если был)
   - полный перечень ИИ-инструментов, IDE, сервисов и для чего каждый
   - ключевые промпты и диалоги с ИИ по этапам/функциям
   - скриншоты этапов: от идеи до готового кабинета, удачные и неудачные варианты
   - как устроены вход, хранение данных и защита — простыми словами
   - что сделано вручную
4. Видео до 5 минут (по желанию), включая использование с телефона

Перед отправкой каждый участник команды сам загружает в профиле: согласие на обработку ПДн, скан студбилета, отметку о согласии с Регламентом.

## Критерии (по 10 баллов, итог — среднее)
1. **Проработанность идеи** — реальная проблема, сценарии вокруг задач, ядро полностью, смелые идеи
2. **Масштаб использования ИИ** — процесс, качество промптов, субагенты, документы для ИИ-агентов (CLAUDE.md и т.п.), работа с ошибками ИИ, ИИ для дизайна/контента, наглядность описания
3. **Имплементация** — работает без ошибок, данные сохраняются, мобильная версия, безопасность, тестовые аккаунты
4. **Качество** — цельный современный дизайн, навигация, пустые состояния/ошибки/загрузка, скорость, доступность
